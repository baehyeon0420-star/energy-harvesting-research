## 3. DHT22 (온습도센서) 테스트

- 라이브러리: Adafruit DHT sensor library v1.4.7
- 배선: DATA → GPIO4, VCC → 3.3V, GND → GND

```cpp
#include <DHT.h>
#define DHTPIN 4
#define DHTTYPE DHT22
DHT dht(DHTPIN, DHTTYPE);

void setup() {
  Serial.begin(115200);
  dht.begin();
}

void loop() {
  float h = dht.readHumidity();
  float t = dht.readTemperature();
  if (isnan(h) || isnan(t)) {
    Serial.println("DHT22 읽기 실패");
  } else {
    Serial.print("습도: "); Serial.print(h);
    Serial.print(" %  온도: "); Serial.print(t);
    Serial.println(" C");
  }
  delay(2000);
}
```

**결과**: 습도 32.5~32.6%, 온도 29.1℃ 안정적 측정.

## 5. INA219 (전류센서) 테스트

- 라이브러리: Adafruit INA219 v1.2.3
- 배선: SDA → GPIO21, SCL → GPIO22, VCC → 3.3V, GND → GND

```cpp
#include <Wire.h>
#include <Adafruit_INA219.h>

Adafruit_INA219 ina219;
bool found = false;

void setup() {
  Serial.begin(115200);
  delay(500);
  found = ina219.begin();
}

void loop() {
  if (!found) {
    Serial.println("INA219를 찾을 수 없습니다.");
    delay(1000);
    return;
  }
  float busVoltage = ina219.getBusVoltage_V();
  float current_mA = ina219.getCurrent_mA();
  Serial.print("전압: "); Serial.print(busVoltage);
  Serial.print(" V, 전류: "); Serial.print(current_mA);
  Serial.println(" mA");
  delay(1000);
}
```

**I2C 스캐너 (진단용, 문제 발생 시 사용)**:
```cpp
#include <Wire.h>
void setup() {
  Serial.begin(115200);
  Wire.begin(21, 22);
  delay(500);
  Serial.println("I2C 스캔 시작");
}
void loop() {
  byte count = 0;
  for (byte addr = 1; addr < 127; addr++) {
    Wire.beginTransmission(addr);
    byte error = Wire.endTransmission();
    if (error == 0) {
      Serial.print("발견된 주소: 0x");
      Serial.println(addr, HEX);
      count++;
    }
  }
  if (count == 0) Serial.println("아무 장치도 못 찾음");
  delay(3000);
}
```

**결과**: 전압/전류 정상 출력, 통신 정상 확인.

### 트러블슈팅 메모
- 최초 I2C 미검출 원인: DHT22를 INA219로 착각하고 테스트했던 것으로 판명
- 이후 전압이 8.10V/0mA처럼 "전압은 있는데 전류가 0"으로 뜨는 현상 반복 발생 → **회로가 물리적으로 열려있다는 신호**(개방회로)였음. 원인은 대부분 헐거운 점퍼선 접촉, 또는 브레드보드 A~E/F~J 블록을 혼동해서 다른 블록에 연결한 경우였음

## 6. 태양전지 발전 특성 측정 (연구계획서 3.3절)

- 회로: `태양전지(+) → INA219 Vin+ → [INA219] → Vin- → 저항 220Ω → 태양전지(-)`
- 측정일: 2026-08-17, 날씨: 흐림

### 결과
- **흐린 날 창가 자연광 + 220Ω 부하**: 전압 0.00V, 전류 0.00mA (검출 안 됨)
- **스마트폰 손전등 대조실험** (약 5cm 거리):

| 조사 조건 | 전압(V) | 전류(mA) |
|---|---|---|
| 근접 조사 (~5cm) | 0.00~0.02 | 0.90 (최댓값) |
| 거리 이격 | 0.00~0.02 | 0.40~0.60 |

### 해석
흐린 날 조건에서는 220Ω 부하 기준 유효 발전량이 관측되지 않았으나, 손전등 대조실험으로 광원 거리(광량)에 비례해 전류가 반응함을 확인 → **회로 및 태양전지 자체는 정상 작동**. 이는 발전량 부족 시 에너지 저장소자의 필요성을 뒷받침하는 예비 관찰로 볼 수 있음. 맑은 날 재측정 및 무부하 개방전압(Voc) 측정 추후 필요.

## 7. 슈퍼커패시터 충전 특성 측정 (연구계획서 3.4절)

- 부품: SC5R5105ZC (5.5V / 1.0F)
- 회로: `3.3V(ESP32) → INA219 Vin+ → [INA219] → Vin- → 저항 220Ω → 슈퍼커패시터(+) / 슈퍼커패시터(-) → GND`
- 측정일: 2026-08-17

### 결과

| 경과시간 | 충전전류 |
|---|---|
| 0분 | 14.20 mA |
| 1분 | 9.50 mA |
| 2분 | 7.30 mA |
| 3분 | 6.15 mA |
| 5분 | 4.20 mA |
| 10분 | 2.00 mA |
| 14분 | 0.95 mA |
| 15분 | 0.61 mA |
| 20분 | 0.34 mA |

### 해석
- 초기 전류(14.20mA)는 이론값(3.3V ÷ 220Ω ≈ 15mA)과 근접
- 시간에 따라 지수적으로 감소하는 전형적 RC 충전 곡선 형태
- 20분 시점 전류(0.34mA)가 무부하 노이즈 수준(~0.2~0.3mA)에 근접 → **사실상 충전 완료로 판단**
- 실측 시정수(τ)가 이론값(RC=220초≈3.7분)보다 큰 것은 점퍼선 접촉저항 등 부가 저항 성분에 기인한 것으로 추정

### 결론
슈퍼커패시터는 220Ω 부하 기준 약 20분 이내에 충전 완료. 다음 단계로 방전 특성 측정을 통해 저장된 에너지의 실사용 가능성을 확인할 예정.

## 8. 슈퍼커패시터 방전 특성 측정 (2026-08-19)

- 부품: SC5R5105ZC (5.5V / 1.0F), 충전 완료 상태(약 3.14~3.30V)에서 시작
- 회로: `커패시터(+) → 저항 220Ω → Vin- → [INA219] → Vin+ → ESP32 GND / 커패시터(−) → ESP32 GND(별도 핀)`
  - 충전 때와 달리 외부 전원을 완전히 분리하고, 커패시터 자신이 저항을 통해 방전하도록 구성
  - Vin+/Vin- 방향이 충전 때와 반대로 연결되어 전류값이 음수(−)로 측정됨 → **절댓값을 실제 방전전류로 사용**
- 코드: `arduino-code/06_supercap_discharge_test.ino` (경과시간·전압·전류를 CSV 형태로 시리얼 출력)

### 결과

| 경과시간 | 방전전류(절댓값) |
|---|---|
| 0분 | 13.20 mA |
| 약 1.5분 | 9.70 mA |
| 약 3.1분 | 7.10 mA |
| 약 3.6분 | 6.50 mA |
| 약 5.9분 | 4.15 mA |
| 약 12.7분 | 1.01 mA |
| 약 22.9분 | 0.20 mA |

### 해석
- 초기 방전전류(13.20mA)는 충전 완료 시점 전압(약 3.14V) 기준 이론값(3.14V÷220Ω≈14.3mA)과 유사한 수준에서 시작
- 시간에 따라 지수적으로 감소하는 전형적 RC 방전 곡선 형태 (충전 곡선과 대칭적인 개형)
- 약 22.9분 시점에 전류가 0.20mA로 무부하 노이즈 수준까지 감소 → **방전 완료로 판단**
- 방전 소요시간(~23분)이 충전 소요시간(~20분)과 비슷한 수준으로, 동일 저항(220Ω) 부하 기준 충·방전 시정수가 대략 대칭적임을 확인

### 결론
슈퍼커패시터는 220Ω 부하 기준 충전(~20분)과 방전(~23분)이 비슷한 시간 내에 이루어지며, 이는 슈퍼커패시터가 빠른 충·방전이 가능한 저장소자임을 실험적으로 뒷받침함. 다만 절대적인 저장 에너지량은 크지 않아(1.0F, 3.3V 기준 E=½CV²≈5.4J), 장시간 전력 공급보다는 순간적인 부하 대응(예: 무선 통신 순간 전류 보조)에 적합할 것으로 판단됨. LIR2032와의 비교를 통해 이 역할 분담의 타당성을 추후 검증할 예정.

## 9. ESP32 센서부 소비전력 측정 — DHT22 (2026-08-20)

- 회로: `+레일 → INA219 Vin+ → [INA219] → Vin- → DHT22 VCC("+") / DHT22 GND, DATA(GPIO4)는 기존과 동일`
- 코드: DHT22 읽기 직전(대기 상태)과 직후(측정 순간)의 INA219 전류를 각각 기록
- 표본 수: 64개

### 결과

| 상태 | 평균 전류 | 범위 |
|---|---|---|
| 대기 상태 | 약 0.00 mA | 노이즈 수준(±0.2mA), 사실상 측정 한계 이하 |
| 센서 측정 순간 | 약 0.90 mA | 0.70 ~ 1.30 mA |

### 해석
DHT22는 대기 중에는 전류를 거의 소비하지 않다가, 실제 온습도 측정을 수행하는 순간에만 약 0.9mA 수준으로 전류가 상승하는 저전력 센서 특성을 실측으로 확인함. 이는 DHT22 데이터시트에 기재된 특성과 부합하며, ESP32의 Deep Sleep 활용 시 센서 측정 구간에서만 짧게 전류가 소모되도록 설계하는 것이 전력 절감에 효과적임을 뒷받침함.

## 10. ESP32 센서부 소비전력 측정 — 정전식 토양수분센서 (2026-08-20)

- 회로: `+레일 → INA219 Vin+ → [INA219] → Vin- → 토양수분센서 VCC / 토양수분센서 GND, OUT(GPIO34)는 기존과 동일`
- 코드: `analogRead()` 직전(대기 상태)과 직후(측정 순간)의 INA219 전류를 각각 기록
- 표본 수: 8개

### 결과

| 상태 | 평균 전류 | 범위 |
|---|---|---|
| 대기 상태 | 약 6.95 mA | 6.90 ~ 7.10 mA |
| 측정 순간 | 약 6.93 mA | 6.70 ~ 7.30 mA |

### 해석
DHT22와 달리, 토양수분센서는 **대기 상태와 측정 순간의 전류 차이가 거의 없음**(둘 다 약 6.9~7.0mA). 이는 이 센서가 내부 발진회로를 이용한 정전용량 감지 방식이라, 전원이 켜져 있는 동안 계속 회로가 동작하며 일정한 전류를 소모하기 때문으로 판단됨. 즉 DHT22처럼 "측정하지 않을 때는 절전"되는 구조가 아님.

**설계적 시사점**: 이 센서는 ESP32가 Deep Sleep에 들어가도 전원이 계속 공급되면 약 7mA를 지속적으로 소모하므로, 실제 저전력 운용을 위해서는 Deep Sleep 진입 전 이 센서의 전원 자체를 (예: MOSFET 스위치로) 차단하는 설계가 필요함. DHT22(약 0.9mA, 측정 순간만) 대비 훨씬 큰 상시 부하이므로 전력 예산 설계 시 우선적으로 고려해야 할 항목.

## 11. ESP32 Deep Sleep 사이클 타이밍 측정 (2026-08-20)

### 측정 방법
ESP32 자체(칩)의 Deep Sleep 전류는 INA219+USB 시리얼 구성만으로는 직접 측정이 불가능함 (Deep Sleep 중에는 CPU가 정지하여 자기 자신의 소비전류를 읽고 보고할 수 없고, 보드 전체 전류를 재려면 USB 전원 경로를 물리적으로 개조해야 하나 이번 연구 범위에서는 제외함). 따라서 **① 각 동작 단계의 소요 시간은 코드로 직접 측정**하고, **② 전류값은 Espressif 공식 데이터시트 및 실측 비교 자료를 인용**하여 결합하는 방식으로 에너지를 추정함.

- 코드: `arduino-code/09_deepsleep_timing.ino`
- 테스트 조건: Sleep 구간 30초(테스트용, 실제 운용 시 600초=10분 예정), Wake 시 DHT22+토양수분센서 측정 → 데이터 포맷팅 → 시리얼 출력 → 재취침

### 타이밍 측정 결과 (3회 반복, 결과 일관됨)

| 단계 | 소요 시간 |
|---|---|
| 센서 측정 (DHT22+토양수분) | 6 ms |
| 데이터 처리(포맷팅) | 0 ms (측정 한계 이하) |
| 전송(시리얼 출력) | 0 ms (측정 한계 이하) |
| **전체 Wake 구간** | **7 ms** |

3회 반복 측정에서 편차 없이 동일한 값(6ms/7ms)이 나와 재현성이 높음을 확인함.

### 참고 전류값 (Espressif 데이터시트 및 실측 비교자료 인용)

| 상태 | 전류(참고값) | 출처 |
|---|---|---|
| Deep Sleep (ESP32 칩 자체, 이상적 조건) | 약 10 μA | [Espressif 공식 데이터시트](https://www.espressif.com/sites/default/files/documentation/esp32_datasheet_en.pdf) |
| Deep Sleep (DevKit 보드 실측, 레귤레이터/USB-시리얼 브릿지 포함) | 약 5 ~ 15 mA | [Hubble Network 실측 비교 자료](https://hubble.com/community/guides/esp32-power-consumption-datasheet-vs-reality/) |
| Active (240MHz, 무선 미사용) | 약 30 ~ 68 mA | [Espressif 공식 데이터시트](https://www.espressif.com/sites/default/files/documentation/esp32_datasheet_en.pdf) |

### 에너지/평균전류 추정 (10분 주기 기준)
Wake 구간(7ms)이 전체 주기(600초) 대비 극히 짧아(듀티비 약 0.0012%), Active 구간이 평균 소비전류에 기여하는 비중은 무시할 수준으로 작음. 따라서 한 주기의 평균 소비전류는 사실상 Deep Sleep 전류값에 의해 결정됨:

$$
I_{avg} \approx I_{sleep} \quad (\because t_{active} \ll t_{sleep})
$$

**중요한 발견**: 이상적인 ESP32 칩 자체의 Deep Sleep 전류(~10μA)와, 지금 사용 중인 **DevKit 보드의 실제 Deep Sleep 전류(~5~15mA, 온보드 레귤레이터·USB-시리얼 칩 등의 상시 소모 포함)** 사이에는 약 500~1500배의 차이가 있음. 즉 Deep Sleep 코드 자체를 아무리 최적화해도, **개발보드에 내장된 주변 회로의 상시 소비전력이 실제 평균 소비전력을 지배**하는 구조임을 확인함.

### 결론 및 설계 시사점
1. Wake 구간(7ms)이 매우 짧아 센서 측정·데이터 처리 자체의 최적화 여지는 크지 않음
2. 실제 저전력 운용을 위해서는 Deep Sleep 코드보다 **하드웨어 선정(베어 모듈 사용, 불필요한 온보드 레귤레이터/USB칩 배제)**이 훨씬 큰 영향을 미침 — 최종 통합 시스템에서는 개발보드 대신 베어 ESP32 모듈 사용을 고려할 필요가 있음
3. 토양수분센서(상시 ~7mA)를 Deep Sleep 중 전원 차단하는 설계(10번 항목)와 함께, 보드 자체의 상시 소모 절감도 병행되어야 실질적인 절전 효과를 기대할 수 있음

## 13. LIR2032 초기 상태 확인 (2026-08-21)

- 부품(TP4056 충전모듈 HW-373, CR2032/LIR2032 코인홀더) 배송 도착
- **문제 발생**: TP4056 충전모듈이 USB 연결 시 LED가 전혀 반응하지 않음 (케이블/포트는 별도로 정상 확인됨) → 충전 실험은 보류, 원인 불명(불량 의심)
- 대안으로 충전 없이 **LIR2032의 초기(출하 시) 전압을 배선 측정으로 확인**
  - 회로: 슈퍼커패시터 방전 실험과 동일한 배선 재사용 — `LIR2032(+) → 저항 220Ω → INA219 Vin- / INA219 Vin+ → GND / LIR2032(-) → GND`
  - 브레드보드에 정상적으로 꽂아 측정 (접촉 안정적)

### 결과

| 항목 | 값 |
|---|---|
| 초기 전압 | 약 3.28~3.29 V |
| 부하 전류(220Ω 기준) | 약 3.2~3.7 mA (거의 일정, 큰 감소 없음) |

### 해석
- LIR2032는 출하 시 완충(4.2V)이 아닌 **부분충전 상태(약 3.28V)**로 온 것으로 보임 (안전을 위한 일반적인 배송 관행)
- 이론값(3.28V÷220Ω≈14.9mA) 대비 실측 전류(약 3.4mA)가 크게 낮음 → 슈퍼커패시터 대비 **LIR2032의 내부저항(ESR)이 훨씬 크다는 정황적 근거**로 해석 가능 (정밀 ESR 측정은 추후 별도 진행 필요)
- 슈퍼커패시터(1F)와 달리 짧은 시간 동안 전류가 거의 감소하지 않음 → **훨씬 큰 에너지 용량(40mAh)**을 가진 저장소자의 특성을 보여줌

## 14. 연구 방향 전환 (2026-08-21)

### 배경
TP4056 충전모듈이 케이블/포트 이상 없음에도 USB 연결 시 LED 무반응 — 재현 시도했으나 해결 안 됨(불량 의심). 재구매 시 980원, 배송 며칠 소요.

### 결정: 슈퍼커패시터 중심 "에너지 효율" 분석으로 범위 조정
LIR2032와의 정식 충·방전 비교 실험은 후속 과제로 미루고, **본 연구는 슈퍼커패시터 기반 시스템의 에너지 효율 병목 분석에 집중**하는 것으로 방향을 조정함.

- 근거: 이미 확보된 데이터(태양광 발전특성, 슈퍼커패시터 충/방전, 센서 소비전력, Deep Sleep 타이밍)만으로도 "에너지가 시스템 어디서 소모/손실되는가"를 규명하는 완결된 분석이 가능함
- LIR2032 관련 데이터(초기전압 등)는 참고자료로 유지, 정식 비교는 향후 TP4056 문제 해결 시 후속 진행
- 이 조정은 원 연구계획서 대비 범위 축소이나, 장비 한계에 따른 정당한 조정으로 레포트에 명시

## 16. 하루 에너지 수지 모델 (2026-08-21)

지금까지 측정한 개별 데이터(9~10번 항목)를 종합하여, ESP32가 10분마다 깨어나 센서를 측정·전송하는 운용 시나리오를 가정하고 하루 소비 에너지를 계산함. 계산은 실측값을 그대로 사용하되, 정확한 실측이 불가능했던 항목(ESP32 칩 자체 Deep Sleep 전류, Active 전류)은 11번 항목에서 인용한 Espressif 데이터시트/실측비교자료 값을 사용함.

### 시나리오 1 — 현재 상태 (최적화 없음)
토양수분센서가 상시 전원 공급(스위치 없음), ESP32는 DevKit 보드(온보드 레귤레이터·USB칩 포함) 사용 가정.

| 소모 요인 | 계산 | 일일 에너지 |
|---|---|---|
| 토양수분센서 상시 소모 | 7mA × 24h × 3.3V | 554 mWh |
| ESP32 DevKit Deep Sleep 상시 소모 | 10mA(5~15mA 대푯값) × 24h × 3.3V | 792 mWh |
| **합계** | | **≈ 1,346 mWh/day** |

### 시나리오 2 — 최적화 적용
토양수분센서를 측정 순간에만 전원 공급(MOSFET 스위치 등), ESP32는 베어 모듈(온보드 주변회로 없음) 사용 가정.

| 소모 요인 | 계산 | 일일 에너지 |
|---|---|---|
| ESP32 베어모듈 Deep Sleep | 10μA × 24h × 3.3V | 0.79 mWh |
| Wake 구간(센서측정+처리+전송, 7ms×144회/일) | 약 50mA(Active 참고값) × 7ms × 144회 × 3.3V | 0.05 mWh |
| **합계** | | **≈ 0.84 mWh/day** |

### 핵심 결과
**하드웨어 선택(베어 모듈 + 센서 전원 스위치)만으로 일일 소비 에너지가 약 1,346배 감소** (1,346 mWh → 0.84 mWh). 이는 11번 항목에서 확인한 "Deep Sleep 코드 최적화보다 하드웨어 선택이 지배적"이라는 결론을 정량적으로 뒷받침함.

### 흐린 날 생존 가능 기간 추정
슈퍼커패시터 저장에너지(E=½CV², C=1.0F, V=3.3V 기준 약 5.4J ≈ 1.5mWh)를 기준으로, 흐린 날(발전량≈0, 6절 참고) 지속 시 저장 에너지만으로 버틸 수 있는 기간(N_days ≈ E_stored/E_consume,day):

| 시나리오 | 생존 가능 기간 |
|---|---|
| 시나리오 1 (최적화 없음) | 1.5mWh ÷ 1,346mWh/day ≈ **약 1시간** |
| 시나리오 2 (최적화 적용) | 1.5mWh ÷ 0.84mWh/day ≈ **약 1.8일** |

### 결론
동일한 저장 용량(슈퍼커패시터)으로도, 시스템 설계(하드웨어 선택 + 상시부하 센서의 전원 관리)에 따라 흐린 날 생존 가능 기간이 1시간에서 약 2일로 극적으로 달라짐. 이는 본 연구의 핵심 주장 — *"제한된 하베스팅 에너지 환경에서는 저장소자 종류보다 시스템 전체의 에너지 병목 제거가 우선"* — 을 뒷받침하는 정량적 근거임.

**주의**: 이 모델은 실측값(센서 소비전력, Deep Sleep 타이밍)과 참고문헌값(칩 자체 전류)을 결합한 추정치이며, 실제 통합 시스템 구성 후 검증 필요 (15번 항목 6~7).

## 17. 향후 발전 방향 (2026-08-21 논의)

원 연구계획서 6절에 이미 "제한된 자연광 에너지를 효율적으로 수집·저장·최소 소비전력으로 사용하는 자립형 저전력 전자 시스템의 설계 및 최적화"가 최종 방향으로 명시되어 있었음. 14번 항목의 범위 조정(배터리 비교 제외)은 이 큰 방향을 바꾼 것이 아니라, 16번 항목의 결과(하드웨어 선택이 최대 지배 요인)가 오히려 이 방향을 더 강하게 뒷받침하는 근거가 됨.

### 단기 — 이번 학기 마무리
**"예측 → 실측 검증"으로 완결**: 16번 항목의 에너지 수지 모델은 현재 예측치임. 베어 ESP32 모듈(DevKit 아닌 순수 모듈)로 통합 시스템을 실제 구성하여, 예측한 절감 효과(약 1,346배)가 실측으로도 재현되는지 검증하는 것이 다음 학기 전 가장 자연스러운 마무리 목표.

### 중기 — 후속 실험 확장
1. **적응형 전력 관리(Adaptive Duty Cycling)**: 현재는 10분 고정 주기로 Wake. 저장 에너지 잔량에 따라 측정 주기를 동적으로 조절하는 알고리즘으로 확장
2. **발전량(E_harvest) 측 개선**: 지금까지는 소비량(E_consume) 최적화에 집중했으므로, 저조도 조건에서 발전량 자체를 늘리는 태양전지 대안(다른 종류 패널 비교 등)과 결합

### 장기 — 확장 실험 방향
- 슈퍼커패시터 전극/구성별 ESR·자가방전 특성 비교 및 응용 적합성 분석
- 저전력 MCU 종류별 Deep Sleep 전류 비교 분석
- 회로 설계 최적화와 저장/발전 소자 선택을 함께 고려하는 저전력 시스템 설계 실험 프레임워크 구성

## 18. 참고 — 최종 발표/논문용 정리 방향
- 브레드보드 배선 자체를 "제품처럼" 정리할 필요는 없음
- 논문에는 브레드보드 사진 대신 **회로도(schematic)**로 정리 예정
- 대회/외부 설명용으로는 통합 시스템이 실제로 작동하는 **짧은 데모 영상** 확보가 효과적
